# Технологический радар целевой архитектуры «Будущее 2.0»

## Статусы
| Статус | Описание |
| --- | --- |
| **ADOPT** | Рекомендуется для использования и является частью целевой архитектуры |
| **TRIAL** | Используется в пилотных проектах и проходит проверку на практике |
| **ASSESS** | Рассматривается к внедрению и требует дополнительной оценки |
| **HOLD** | Не рекомендуется для новых решений, используется только в легаси-системах |

## Архитектурные паттерны
| Паттерн | Статус | Обоснование |
| --- | --- | --- |
| Event-Driven Architecture | ADOPT | Основной способ взаимодействия между доменами через события |
| Domain-Driven Design (DDD) | ADOPT | Используется для выделения доменов и bounded contexts |
| Data Mesh | TRIAL | Внедряется поэтапно через доменные дата-продукты |
| Microservices | ADOPT | Обеспечивает независимое развитие сервисов |
| API Gateway | ADOPT | Единая точка входа для клиентов и внешних систем |
| Strangler Fig | ADOPT | Позволяет постепенно заменять легаси-компоненты |

## Ключевые принципы выбора технологий
- **Open Source first** – предпочтение open source решениям
- **Cloud-native** – Yandex Cloud + Kubernetes
- **API-first** – все сервисы через REST/gRPC/события
- **Security by Design** – шифрование, RBAC, аудит
- **Compliance** – соответствие 152-ФЗ и банковскому регулированию

## Вывод
Целевой технологический стек ориентирован на построение облачной событийной платформы с использованием принципов Domain-Driven Design, Event-Driven Architecture и Data Mesh.

Основу решения составляют Kafka, Kubernetes и доменные микросервисы. Legacy-компоненты (Apache Camel, SQL Server 2008 и PowerBuilder) сохраняются только на период миграции и не рассматриваются как часть целевой архитектуры.
